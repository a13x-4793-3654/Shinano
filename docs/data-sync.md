# 暗号化ライブラリーとフォルダー同期

この版は macOS / Windows を対象にしたアプリ暗号化フォルダー同期です。外部クライアントのクラウドへの到達・取得完了を証明する仕組みではありません。実 Microsoft 365、実 OneDrive、Windows の DPAPI や macOS↔Windows 間の動作はこの開発環境では検証していません。

## 対象と対象外

| 対象 | 境界 |
| --- | --- |
| プロファイル | UUID・表示名・色。サイトの認証済みアカウントを証明するものではありません。 |
| ブックマーク | 明示保存した HTTP(S) URL 全体とタイトル。URL 内の機密情報も保存され得ます。 |
| 履歴 | 90日以内の確定したメインフレーム訪問。初期設定はパス・実タイトルを記録し、クエリ・フラグメントは除外します。 |
| TOTP | 登録ごとの明示許可が必要です。main が正規のキーとパラメーターを再暗号化し、相手 PC は自分の OS 鍵でローカル保存します。 |
| 対象外 | Cookie、ログイントークン、パーティション DB、タブの入力・順序・復元情報、ダウンロード、OS デバイス ID・証明書、他の認証器・資格情報管理ツール。 |

パスキー / WebAuthn の登録・署名・同期は未実装です。金庫の解除も、WebAuthn の user verification (UV) やサービス側のサインインにはなりません。

## 操作と復旧

最初の PC で「同期」を開き、ネイティブのフォルダー選択から保存先を選びます。アプリは選んだ場所の `Shinano Sync/<vault-uuid>/` だけを扱います。リポジトリ・アプリ・userData 内、シンボリックリンクやジャンクションを保存先にしません。外部クライアントのログイン、同期対象の設定やクラウドアカウントの操作はユーザーが行ってください。

新しい金庫には、確認入力した強いマスターパスフレーズを使用します。20 Unicode code points 以上、1,024 UTF-8 bytes 以下です。長さだけで十分な強度を保証しません。複数のランダムな単語等、推測しにくく他で使っていないものを選んでください。入力は UTF-8 の正確な文字列として扱い、空白の削除・大小文字変換・Unicode 正規化を黙って行いません。

ランダムな復旧キーを一度だけ表示します。**安全な場所に保管し、確認してから作成を完了してください。** フォーカス喪失や画面切替で機密表示は消去され、未完了の設定はキャンセルされる場合があります。手元に控えるか、明示的に選択・コピーした場合は作成完了後に信頼できる保管先へ保存してください。アプリは平文の復旧ファイルを書かず、クリップボードへ自動コピーしません。キー、パスフレーズ、QR や実ユーザーデータをチャット、issue、PR に貼らないでください。

フォルダー選択・金庫作成・金庫への接続だけでは既存の TOTP は送信されません。プロファイルごとに表示するブックマーク・履歴の共有範囲と件数を確認します。TOTP はさらに登録 UUID ごとに共有を許可します。別 PC は同じ金庫を選び、パスフレーズまたは復旧キーで解除して、プロファイルと TOTP を個別に取り込みます。同じ表示名だけを理由にローカルのプロファイルや認証キーを置き換えません。

この端末での記憶を選択すると、OS が保護するローカルの解除鍵を使えます。記憶しない場合は再起動後にパスフレーズまたは復旧キーが必要です。Keychain 等の許可は OS の通常の UI に従ってください。Shinano はアクセス許可を自動承認せず、暗号化が利用できないときに平文・固定パスワードへ切り替えません。

| 状況 | 動作 |
| --- | --- |
| 間違ったパスフレーズ / 復旧キー | 明示エラー。既存の金庫やローカル登録を初期化しません。 |
| 破損・未対応の形式・未取得ファイル | 同期を保留し、暗号文を保持します。フォルダーの取得状態を確認して再読み込みしてください。破損したファイルの手動復旧には信頼できるバックアップが必要な場合があります。 |
| フォルダーの消失・権限・空き容量不足 | ローカルの未送信操作を保持し、成功とは表示しません。対象フォルダーを再び利用できる状態にしてください。 |
| OS 鍵を利用できない | 対象の保存・復号を拒否します。既知のローカルプロファイルや TOTP 暗号文の削除に、秘密鍵の復号は必要ありません。 |
| 作成完了中の画面ロック / 中断 | 消去した一時鍵を再有効化せず、未完了として知らせます。既に空の金庫の鍵情報が保存されていた場合は同じフォルダーを再選択し、作成時のパスフレーズ / 復旧キーで接続できます。プロファイルや TOTP の共有はまだ許可されていません。 |
| 移行中断 | profile UUID に結び付けた暗号化 intent と元の TOTP の暗号文を保持します。同じ共有 head なら再開でき、変化・削除・競合したときは自動再取り込みしません。「未完了の TOTP 移行を取り消す」で保存前のローカル登録に戻せます。読み取れない暗号文は勝手に置き換えません。 |
| すべての解除手段を喪失 | パスフレーズ・復旧キー・利用できる記憶済み端末がなければ永久に復元できない場合があります。サーバーの合鍵や回復バックドアはありません。 |

## 履歴のプライバシーと期限

通常の履歴には `origin + pathname` と bounded なタイトルを記録します。クエリ・フラグメント、HTTP 本文、ヘッダー、フォーム値、Cookie、referrer は履歴レコードや outbox に入りません。iframe や広告リクエストを訪問として列挙しません。

メインフレームの確定と完了後、1.5秒の静かな期間を待ちます。置き換えられた候補や失敗・閉じたタブを破棄します。HTTP リダイレクトや短い JavaScript 遷移を別々の訪問にせず、同じ文書内のクエリ・フラグメントだけの変更を重複記録しません。既知の認証ホスト・callback・OAuth/SAML 系のパスやキー付き URL は追加の best-effort 除外対象です。

**これでパス・タイトル中の秘密をすべて検出できるわけではありません。** 長い認証中間遷移、未知の認証方式、URL の意味は完全には判定できません。必要なプロファイルでは「サイトのみ」または記録 OFF を使用してください。「サイトのみ」はオリジンとホスト名を保存し、実タイトルは保存しません。設定変更は以前の履歴を自動書換えしません。クエリ・フラグメントを省くため再表示が元の画面と一致しない場合もあります。

保存した訪問時刻が90日の境界以下になった記録は期限切れです。起動、一覧取得、取り込み、定期処理に適用し、削除境界を後退させません。共有側の clear-through / retention fence は最大値で統合し、遅いレプリカの古い訪問を再表示しません。大きく進んだ時計は同期エラーとして確認を促します。信頼できる外部時刻サーバーや絶対的な時刻保証を提供するものではありません。

認識・認証した期限切れの共有訪問ファイルを個別に清掃します。取得できないフォルダー、バックアップ、クラウドの旧バージョン、オフライン PC の物理的なファイルを同時に消去できるとは保証しません。期限切れファイルが再配送されても再表示しません。

## 削除・ロック・同期停止の意味

- **この端末だけの項目削除 / 履歴クリア:** ローカル suppression / clear-through を記録し、他の PC の記録を削除しません。同じ古い記録が再配送されても、この端末では再表示しません。ローカルで削除した未送信の履歴は送信前に除去します。
- **共有金庫からの項目削除:** 暗号化した terminal tombstone を追記します。同じ記録 ID の古い編集は復活させません。再作成する場合は新しい記録 ID を使います。
- **従来のローカルプロファイル削除:** 全タブを閉じ、ローカルのサイトデータ・TOTP・ライブラリー・未送信変更を削除します。先に削除 intent と永続 local suppression を残し、次回起動前のパーティション掃除を従来どおり再試行します。共有金庫は消しません。
- **共有プロファイル削除:** 共有メタデータ・子レコード・共有認証キーに削除を伝えます。受信 PC のブラウザープロファイルや Cookie・タブを遠隔で消すことはなく、共有接続を外します。その後の端末専用ブックマーク・履歴は新しいローカル namespace を使い、移行前のコピーを自動復活させません。Entra アカウントやサービス側 MFA は変更しません。
- **TOTP のローカル置換 / 削除:** 以前の共有登録を勝手に置き換えません。明示的に再接続するまで再取り込み・送信を抑止します。未送信の TOTP 共有と未完了の移行は停止します。全 PC へ反映したい場合は同期画面で別途確認します。
- **同期金庫のロック:** 共有鍵のメモリー保持を解除し、同期や共有 TOTP の利用を止めます。別の OS 保護付きキャッシュにあるローカル閲覧データや、既にサインイン済みの Web セッションまですべてロックする機能ではありません。画面ロック / suspend でも共有鍵の世代を無効化します。
- **端末の記憶の削除 / 同期接続の解除:** この端末の既知の解除鍵・接続を削除し、自動送信を止めます。選択フォルダーや他の端末のコピーを削除しません。別の金庫へ送るには、新しい接続・範囲・TOTP の許可が必要です。

ファイル削除は SSD、swap、バックアップ、メモリー、クラウド履歴からの完全消去を保証しません。同一 OS ユーザー権限で動く悪意あるプロセスへの完全な防御でもありません。

未完了の TOTP 移行があるときは、完了または明示的な取り消しの前に同期接続を解除しません。取り消しの intent も暗号化して先に記録するので、途中で終了しても古い取り込みを再実行せず、保存前の登録への復帰を再試行できます。共有プロファイルが削除された場合にも、未完了の移行や破損したコピーを黙って捨てず、取り消し・復旧の確認を求めます。

## 暗号形式 v1

暗号プリミティブは Node の OpenSSL 実装を使用します。独自の暗号アルゴリズム、新たなクラウド暗号化サービス、追加の暗号ライブラリーは導入していません。**Shinano の新しい同期プロトコル全体が独立監査済みという意味ではありません。**

| 項目 | v1 |
| --- | --- |
| 金庫キー | ランダムな 32-byte root key。renderer へは返しません。 |
| パスフレーズ KDF | 非同期 scrypt、`N=131072, r=8, p=1`、ランダム 32-byte salt、出力32 bytes、`maxmem=256 MiB`。同時 KDF は1つに制限します。 |
| レコード暗号 | AES-256-GCM、12-byte nonce、16-byte tag。暗号化ごとに新しい UUID・salt・nonce を生成します。 |
| 鍵分離 | HKDF-SHA-256 で用途・形式・vault/envelope UUID に結び付けた object key を導出します。 |
| 認証対象 | 外側の用途・形式・ID・暗号パラメーターを AAD に、種類・profile/record ID・writer/sequence・親 revision・値を暗号化 payload に含めます。 |
| wrapping | passphrase slot と recovery slot で root key を包み、世代・親世代・KDF・両 slot を root-key HMAC で認証します。 |
| ローカル保護 | 別のランダムな local data key と real `safeStorage`。`basic_text` / 不明な Linux backend は拒否します。 |

パスフレーズ変更は新しい immutable wrapping 世代を追加し、データキーを保持します。同時変更の head は明示的な競合です。解除できる端末から新しいパスフレーズを確認入力して解決します。**古い wrapping と古いパスフレーズ、root key を持つオフライン端末は失効しません。** 強制端末失効、全データの再鍵化、クラウド履歴の暗号学的消去を実装したとは扱いません。

既知の wrapping 世代・ID をローカルに記憶し、観測済みの後退やファイル欠落を検出します。しかし AEAD は完全な rollback 防御ではありません。新しい PC、ローカル状態を失った PC、ファイルを隠すクラウドに対して、唯一の「世界最新状態」を証明する外部の信頼アンカーはありません。

共有フォルダーには固定のアプリディレクトリ名、vault/envelope UUID、形式・暗号 framing と暗号文だけを置きます。プロファイル名、タイトル、URL、TOTP ラベル・秘密鍵は平文で置きません。ファイル数・長さ・更新の頻度などは見えるため、トラフィック解析を隠す方式ではありません。ユーザーや外部アプリが選択フォルダーに置いた未知のファイルまで暗号化・削除することはありません。

## 競合・配送・中断

各操作は immutable な UUID・writer UUID/sequence と因果関係を持ちます。後の編集は観測した親 revision だけを置き換え、別々のオフライン編集は両方の候補を残します。表示順は決定的ですが、時刻による last-writer-wins で片方の URL や秘密鍵を捨てません。TOTP の異なる key/registration や、同じ登録 ID の内容の相違は特に自動選択しません。

入力のサイズ、canonical JSON/base64、UUID、未知フィールド、種類、暗号の tag と内外 ID を検査します。親レコード・プロファイル・ファイルが未取得なら保留します。同じ論理操作の重複配送は冪等で、同じ ID / writer sequence の異なる内容はエラーです。外部クライアントの conflict-copy 名も、認識できる UUID prefix と認証内容で判定します。

共有ファイルの公開は、完全に書き込み・fsync した暗号化 staging を **ローカルの原子的・非上書き hard link** で最終名へ公開し、読み戻して確認する方式です。最終ファイルは通常の暗号化バイト列であり、クラウドが hard link や rename をトランザクションとして複製することには依存しません。中断した staging は暗号文のまま保持し、記録として解釈せず新しい暗号化コンテキストで再試行できます。公開後の認証できないファイルを別の内容で黙って上書きしません。

このため、通常ファイル・exclusive create・hard link を提供するローカルファイルシステムが必要です。APFS / NTFS を想定していますが、Windows / OneDrive の実機検証ではありません。機能を提供しないネットワークドライブ等では明示エラーにし、安全でない上書き方式へ切り替えません。OS API だけで、同じ OS ユーザーが全ファイルシステムを競合変更できる攻撃を完全に防げるとは保証しません。

`fs.watch`、端末間のロック、可変の whole-vault snapshot は同期の正しさの根拠ではありません。取得・送信は直列化し、定期ポーリングと明示的な再読み込みを行います。状態表示はローカル保存、選択フォルダーへの保存、ロック、未取得/利用不可、競合、形式/整合性エラーを区別します。外部クライアントのクラウド到達は分かりません。

## 保存上限と形式の更新

| 対象 | 上限 |
| --- | --- |
| この端末のプロファイル / タブ | 20 / 50 |
| 金庫内の profile UUID / writer UUID | 128 / 32 |
| 表示対象のブックマーク / 90日訪問 | 5,000 / 50,000 |
| 論理操作 | 100,000。非履歴操作は50,000、その最後の1,024枠を削除・制御に予約します。 |
| 金庫の1回の列挙 / 暗号文読み取り | 120,000 entries / 512 MiB |
| 1操作 / wrapping | 64 KiB / 16 KiB |
| materialized record payload | 64 MiB。ローカル journal の読み込みにも別途件数・byte 上限があります。 |
| URL / タイトル / 検索 / 1ページ | 8,192 / 160 / 256 文字、100件 |
| 親 revision / wrapping 世代 / 同時 wrapping heads | 32 / 64 / 8 |

移行用の journal と別金庫への明示コピーにもローカルの操作枠が必要です。上限到達時に、未期限切れ履歴やブックマークを黙って間引きません。操作を保留し、元のデータを保持します。immutable な非履歴ログを無期限に保存できる構成ではなく、制御枠や byte budget まで尽きれば削除操作も完了したとは表示しません。全端末が古い編集を忘れたと推測する危険なログ圧縮は行いません。

v1 では固定の暗号パラメーターと厳密な record kind/version だけを受け付けます。未知の形式を既定値に変換して再書き込みしません。将来の KDF/record migration は明示的な対応が必要です。復旧のために保存ディレクトリを直接編集したり、OS-bound ciphertext を別ユーザー/PC へコピーすれば動くとは保証しません。

## 将来の main/native 契約（パスキーは未実装）

現在の runtime record union は profile、bookmark、visit、削除/履歴制御、TOTP のみです。任意のバイナリ秘密を renderer から格納・取り出しする API はありません。

将来の passkey adapter は別の厳密な namespace/version を持ち、profile UUID・credential/RP/userHandle・COSE algorithm・検証済み portable key・discoverable/credential-protection・正確な BE/BS を native 所有者と合意してから追加します。小さい接続契約は bounded `find(profile, RP, allow/exclude IDs)`、main/native 限定の scoped key lease、durable insert、共有 tombstone、失効通知です。

lease は profile/RP/credential/revision と世代に結び付け、lock、recovery/rekey、profile 削除、整合性エラーや credential 競合で破棄します。同じ credential ID の不変情報が異なれば隔離・拒否し、鍵を LWW で差し替えません。insert の応答前にローカル commit を完了させますが、その応答やフォルダー書込を remote backup / BS=true とみなしません。UP/UV、署名、origin/frame binding、counter と実際の認証経路は native 実装の責務です。金庫の解除を UV と扱う汎用 `sign` / `unseal` IPC は公開しません。

## 検証範囲

ユニット試験は公開 RFC TOTP ベクトルと架空の閲覧データを使用し、異なる疑似 OS 保護鍵の2インストール、重複・並べ替え・遅延した配送、同時編集・削除、厳密な90日境界、古い記録の再投入、移行中断、誤キー・改変・サイズ/件数上限を扱います。

Electron E2E は別々の一時 userData とローカル複製フォルダーで、実 `safeStorage`、明示 TOTP 取り込み、UUID/コード一致、再起動、Cookie が相手へコピーされないこと、実 main-frame 履歴、テキスト安全な描画と実 foreign WebContents の IPC 拒否を確認します。クリップボードの試験はテスト側でコピー処理を捕捉し、実クリップボードを上書きしません。

同一マシンの試験は異なる OS の証明ではなく、保護が利用できず skip したケースも成功とは数えません。実アカウント、実クラウドフォルダー、実ユーザーの認証情報、試用中の別アプリを試験に使いません。
